# AIWorkSpace｜产品需求 V1

状态：**用户已确认**（2026-10-27）。本文件记录产品需求，不代表全部功能已开发。

## 1. 定位和目标

以 ChatGPT 为主要自然语言/语音入口的个人 AI 工作台：AI 理解、记录、拆解、分析和跟进工作；网页集中查看、修改和人工确认。**先个人使用，未来扩展团队。**

## 2. 总体功能（分期实现）

| 功能 | 目标 |
|---|---|
| 工作输入 | 文字、语音；可将一段输入拆为多个事项 |
| 项目结构 | 项目、任务、明确编号的执行步骤；主要所属项目及相关项目 |
| 任务字段 | 负责人、状态、优先级、截止日期、计划执行日期、下次跟进日期（分开） |
| 工作台首页 | 今日需要亲自做、审核/决策、跟进他人、临近到期和风险事项 |
| 任务查询 | 按稳定编号、关键词/自然语言、项目、状态、时间等查找 |
| AI 助手 | 识别、归类、拆解、提出方案与优先级建议；能做的工作按授权执行 |
| 进度管理 | ChatGPT 文字/语音、网页操作、AI 执行结果均可更新进度 |
| 他人跟进 | 负责人、期限、最新进展、待反馈、下次跟进 |
| 想法与成果 | 将想法尽量转成行动；成果由用户审核后归档 |
| 历史与记忆 | 保存重要状态/计划/责任/决策变更及原因；支持跨对话读现有台账 |
| 主动提醒 | 截止/逾期、长期无进展、风险、冲突及汇总；网页、AI、手机渠道分期验证 |
| 数据安全 | 持久保存、备份恢复、避免离线/并发变更静默覆盖，引用有出处 |

## 3. 已确认的业务规则

1. 一次输入多个事项时，AI 自动拆分；需要确认的整理结果先展示再入账。
2. 缺乏必要信息先询问；例行新增、分类、进度更新及设置跟进日期可按已授权规则执行。
3. 重大优先级冲突，由 AI 给建议，用户确认后改变。
4. **所有任务完成状态只能由用户手动确认**；重大成果归档及冲突裁决也需要用户确认。
5. 他人负责的事项记录负责人、进度、期限、等待/阻碍原因及下一步，由用户与他人沟通。
6. 每个事项及明确步骤有稳定编号；支持按编号精确引用。
7. 一个事项以一个项目为主要归属，可关联其他项目；允许跨项目分析。
8. 只长期保留必要的结构化结果和重要历史，原始口述一般不长期保存全文。
9. 大项目先读覆盖历史的结构化总账，必要时深入明细；新对话主动读取既有历史。
10. 可检索用户已授权资料；发现资料新信息先提出建议，确认后更新台账，尽量提供编号及来源。
11. 新指令与现有状态相冲突时，明确指出并询问，不擅自改写。

## 4. 第一版：最小双向任务闭环

**仅需实现：**

1. ChatGPT 接收一项工作并整理为结构化任务。
2. 安全保存该任务，关闭对话后仍能读取。
3. 网页从同一份数据展示任务列表。
4. 用户在网页修改任务内容或进度，保存后 ChatGPT 能读取正确的新状态。
5. 明确“未保存 / 保存成功 / 读取失败”等基本反馈，避免静默丢失。

**验收标准：** AI 创建 → 网页可见 → 网页修改 → AI 读到更新后的值；重复操作和重新打开页面后仍正确。使用虚构测试数据。

项目/步骤完整功能、想法库、复杂筛选、人员跟进、自动提醒、手机推送及团队权限属于后续阶段，不在第一版一次完成。

## 5. 技术与费用约束

- 优先使用现有 Google Drive 与 Windows 电脑；可接受 ChatGPT 对话与网页分离。
- 优先云端维护开发内容与数据交互，不默认新增付费 Google Cloud 或 AI API。
- 存储结构、同步及备份方案需要先以最小实测确认；不能将技术探针当作正式产品验收。
- ERP 等敏感系统接口及外部平台对接不作为第一版范围。
- Public GitHub 只保存产品代码、非敏感设计和虚构测试数据；真实台账及凭证不进入仓库。

## 6. 软件更新（用户确认，2026-10-30）

1. 工作台页面显示当前语义版本号和构建标识。
2. 用户可在网页内检查固定公开 GitHub 仓库 yudacheng666/AIWorkSpace 的 main 最新构建；发现更新后，点击一次“立即更新”即可下载、校验、备份、安装并自动重启本机服务，不再反复手动下载/解压/复制程序。
3. 更新只操作明确列出的应用程序文件；不得改动 --data-dir 下的任务、项目、步骤事件及历史数据。
4. 更新前备份旧程序；下载、校验、安装或新版本启动失败时保留/恢复旧版本，并给出明确结果。
5. 更新源固定为官方公开仓库和已校验的 commit；不接受任意 URL、不执行远程脚本，不要求 GitHub Token、额外付费服务或远程访问。
6. 存在未保存草稿时禁止开始更新；更新时安全停止旧服务，并保留原端口和 --data-dir 参数重启。
7. 首次下载后允许在网页中完成后续更新；初次安装未登记 commit 时，第一次网页更新用于登记并对齐最新 main 构建。


## 7. UI V2 多视图改造（2026-10-31，按已批准分期推进）
- 基于确认过的 V2 交互原型，按阶段实现统一页面框架、任务详情抽屉和列表／看板／日历／日期甘特图。
- 看板依照现有状态与冲突分组，不能依靠拖拽未经明确保存而改状态；任务编辑仍从详情面板走既有确认流程。
- 月历可在截止日期、计划执行日期、下次跟进日期之间切换，不互相推断。没有日期的任务不得默默丢弃。
- 日期甘特图仅显示计划日与截止日及其间的日期窗口；不代表工时、实际进度或依赖关系。日期缺失、逆序或任务冲突时不强行画出计划。
- 列表、看板、月历和甘特图共享既有筛选及任务详情；视图本身只读，不新增数据模型、事件或写入端点；未保存草稿保护继续生效。
- 不自动合并、升级或接触真实工作数据。
