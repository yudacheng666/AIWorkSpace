# AIWorkSpace｜工作档案与工作记录使用说明（2.4.0 组合候选）

适用对象：日常使用 AIWorkSpace 的本人，不要求懂程序。本文配合 docs/WORK_RECORDS_DESIGN.md 阅读。2.4.0 尚未合并或安装到正式电脑。

## 一、做过的临时工作如何补记

进入左侧“工作记录”，在“补记已做工作”填写实际做过的事和发生日期即可保存。内容和日期必填；项目、已有任务、成果与耗时可以留空。系统会另外保存真正录入时间。选中“归入我的成果库”可以将重要成果收入下方成果库。

如该工作属于已有任务，可选主关联任务；如涉及数个任务或具体执行步骤，可在“关联任务或步骤”中选择对象和进展/成果/后续行动关系，再点“添加关联”。只选择但不点击添加，不会产生该项关联。任务会保留原状态，不因补记自动标为完成。需要关联 Google Drive 会议纪要、报价资料或成果文件时，在证据名称和链接中填写，再点“关联证据”。只保存链接，不复制或开放文件权限。

## 二、原始笔记如何整理

来不及整理时，先在“待整理收件箱”写入原话并暂存，可不选发生日期或项目。点击一条待整理笔记的“整理成工作记录”，只会将原文预填到上方表单，核对后点击保存才真正形成工作记录。来源已处理后，待整理数会下降。系统拒绝把同一来源再次处理成第二条记录，原始笔记仍保留。无需处理的笔记可以明确确认“忽略”，不会删除原文。

## 三、如何查看工作的来龙去脉

“工作轨迹”按照实际工作发生日期列出补记和已有任务的人工确认完成历史，两者分别计数。可以按关键词、日期区间、项目筛选。点击任务详情中的“关联工作记录”可返回与该任务及其执行步骤有关的历史事实。步骤转换或源对象暂时未同步时保留原始引用，不凭名称自动合并和改绑。

“个人成果库”只展示本人明确选入的工作记录，保留原始内容、成果、日期、项目及证据资料，供将来的项目回顾或简历撰写使用。它不自动判断绩效高低。

## 四、如何形成日报、周报、月报

在“工作总结”里选择日报、周报或月报，选一个该周期内的日期，可选择项目范围。点击“生成来源底稿”，系统依据实际工作记录和已由用户确认完成的任务事件列出来源及数据；此时不写文件、不调用 AI。核对底稿后可以补充问题、解决过程、后续行动，并按需勾选“我已核对内容”保存。历史总结可以打开修改，旧版本不被覆盖。

点击“复制供 ChatGPT 分析”仅复制文本到剪贴板，需要本人到 ChatGPT 对话粘贴并请求润色、提取成就或分析，不表示网页在后台自动运行 ChatGPT。如果使用 Google Drive 连接器读取相关资料，仍应遵守文档权限及项目数据校验规则。

## 五、集中验收流程

仅在 2.4.0 组合候选全部测试通过后，使用 GitHub Actions 的独立 Windows 体验附件，不需要更改正式工作台。建议在临时测试目录中：
1. 创建一个虚构项目和任务，并给任务添加一步。
2. 暂存一条前几天的工作原文，整理为工作记录，关联虚构任务/步骤及虚构证据链接。
3. 补记另一条已完成工作，确认短编号、发生日期、录入日期和成果标识。
4. 编辑工作记录并刷新，确认内容仍在、日期修订不改变编号。
5. 从任务详情点“关联工作记录”查看历史。
6. 生成本周周报，人工补充、保存、再次修订，查看成果库。
7. 测试未保存修改时切页是否提醒，不使用真实工作资料。

体验附件使用独立临时服务和随机端口，不读取现有 Google Drive 工作台目录。启动脚本为 start_ui_v2_preview.bat；关闭启动窗口后临时测试数据清理。真正的两台公司电脑数据同步、断网与重连尚未实测，需要独立授权后再做增量验收。

## 六、功能边界

本机程序没有内嵌 AI、不使用模型 API，不会自动将会议识别为任务或将事实写成已完成。AI 分析由 ChatGPT 对话按用户要求进行；工作台的来源底稿不等于 AI 总结。任何真实数据、文件链接、人员和公司材料不得提交公开 GitHub。


## 七、2.5.0：从已做工作提出后续待办建议

1. 在「工作记录」的某条事实下点「安排后续待办」，或在「从工作记录安排后续待办」选择原工作记录。
2. 点「复制 ChatGPT 分析说明」，主动粘贴到 ChatGPT 对话。请先确认内容允许发送到该对话。
3. ChatGPT 若识别到可信的未来工作，会按照说明返回最多 5 条 JSON 建议。把 JSON 原样粘贴回工作台，点击「检查建议和重复任务」；此时仍不会新建任务。
4. 工作台列出同项目可能重复的现有任务。可以选「关联已有」，或逐条核对后点击「确认新建待办」；操作须在确认弹窗中批准。同名任务禁止从此入口重复建，其他相似任务须再次确认；新任务起始为待处理而不是已完成。
5. 保存成功后原工作记录会显示衍生任务的关联，后续可以继续追溯。若来源记录被其他设备修改，工作台提示冲突，应重新检查建议，不要机械重试或手工覆盖。

网页没有内嵌模型，不自动读取 ChatGPT 回复，也不能保证已发现所有语义重复任务。真实双电脑 Drive 同步、历史误建任务转换及职业履历自动撰写仍属于后续独立阶段。

## P3：整理一段包含多件事情的工作笔记
1. 打开「工作记录 → 待整理收件箱」，写下原话并暂存。点击对应笔记「拆分多条事实」。
2. 原话按行分得清时点击「按换行拆分」；复杂文字点击「复制给 ChatGPT 整理」，将剪贴板文字主动粘贴到对话；得到 JSON 后贴回「ChatGPT 整理建议」，点击「核对拆分建议」。
3. 逐条检查：引用的原文必须真实存在，发生日期必须确定；尚未发生的计划或对方承诺不能写成完成成果。每条事实单独点击「核对后保存这一条」。遇到重复、交叉、来源不一致时系统拒绝写入，保留原文。
4. 未来待办建议与工作事实分开展示。先保存有关事实，再点击「用此事实审核后续待办」，到已有待办建议区检查重复任务并明确确认，才会创建或关联。
5. 不再有待保存片段时，可清空拆分草稿，再点击收件箱中的「确认此笔记已整理完」。完成只是标记原文已整理，原文和工作记录仍永久保留。
6. 在「项目阶段事件线」选择项目和起止日期，查看按日期归并的进展；点击「复制来源供 ChatGPT 整理」会主动复制完整个人阶段资料，不会自动发送。向他人汇报时请使用「工作总结 → 汇报版」重新挑选需要汇报的事件。
**注意：** 工作台网页不自带 AI，也没有付费 API；本功能是 ChatGPT 复制／粘贴与人工确认的协同，不是后台自动记录。真实双电脑 Drive 同步和新旧软件混用需单独验收。

## P1–P3 整体验收：一条工作从记录到汇报

使用隔离的虚构项目，进入「工作记录」页后可以通过顶部「我要」直接跳到对应区域，建议按以下顺序体验：

1. 在「整理零碎笔记」保存两条不同日期的已发生工作；可从「待整理收件箱」拆成两条事实，每条核对日期后分别保存。
2. 修改 ChatGPT 返回的拆分 JSON 再尝试保存，应提示「重新核对」；切换其他原文时若有未保存草稿，应先提醒。重开已存过的片段显示「已保存」，不会再创建重复记录。
3. 查看「项目阶段事件线」，核对事实日期和项目关联。同一 RECORD 在步骤、任务、项目多处可见，但阶段统计应只算一条。
4. 点击「用该项目生成月度汇报」，系统只会把项目、阶段结束日期的**所在月份**和「汇报版」带入工作总结，不会直接保存。点击「生成来源底稿」，逐条勾选适合汇报的事件，人工核对正文后保存。未选工作仍在个人工作轨迹里。
5. 若完成确认先到另一台电脑、事实记录还没同步齐，该笔记应显示需要核查；源事件全到齐后才恢复「已整理」。不要为消除提示而手工覆盖或删除原始文件。

以上 GitHub 测试均使用虚构隔离数据，不等于已在公司的两台电脑上完成 Google Drive 离线／重连验收。真实工作台上线前，所有写入客户端应统一版本并备份数据。
