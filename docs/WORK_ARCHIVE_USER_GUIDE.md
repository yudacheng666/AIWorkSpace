# AIWorkSpace｜工作档案与工作记录使用说明（2.4.0 组合候选）

适用对象：日常使用 AIWorkSpace 的本人，不要求懂程序。本文配合 docs/WORK_RECORDS_DESIGN.md 阅读。2.4.0 尚未合并或安装到正式电脑。

## 一、做过的临时工作如何补记

进入左侧“工作记录”，在“补记已做工作”填写实际做过的事和发生日期即可保存。内容和日期必填；项目、已有任务、成果与耗时可以留空。系统会另外保存真正录入时间。选中“归入我的成果库”可以将重要成果收入下方成果库。

如该工作属于已有任务，可选主关联任务；如涉及数个任务或具体执行步骤，可在“关联任务或步骤”中选择对象和进展/成果/后续行动关系，再点“添加关联”。只选择但不点击添加，不会产生该项关联。任务会保留原状态，不因补记自动标为完成。需要关联 Google Drive 会议纪要、报价资料或成果文件时，在证据名称和链接中填写，再点“关联证据”。只保存链接，不复制或开放文件权限。

## 二、原始笔记如何整理

来不及整理时，先在“待整理收件箱”写入原话并暂存，可不选发生日期或项目。点击一条待整理笔记的“整理成工作记录”，只会将原文预填到上方表单，核对后点击保存才真正形成工作记录。来源已处理后，待整理数会下降。系统拒绝把同一来源再次处理成第二条记录，原始笔记仍保留。无需处理的笔记可以明确确认“忽略”，不会删除原文。

## 三、如何查看工作的来龙去脉

“工作轨迹”按照实际工作发生日期列出补记和已有任务的人工确认完成历史，两者分别计数。可以按关键词、日期区间、项目筛选。点击任务详情中的“关联工作记录”可返回与该任务及其执行步骤有关的历史事实。步骤转换或源对象暂时未同步时保留原始引用，不凭名称自动合并和改绑。

“个人成果库”只展示本人明确选入的工作记录，保留原始内容、成果、日期、项目及证据资料，供将来的项目回顾或简历撰写使用。它不自动判断绩效高低。

## 四、如何形成日报、周报、月报

在“工作总结”里选择日报、周报或月报，选一个该周期内的日期，可选择项目范围。点击“生成来源底稿”，系统依据实际工作记录和已由用户确认完成的任务事件列出来源及数据；此时不写文件、不调用 AI。核对底稿后可以补充问题、解决过程、后续行动，并按需勾选“我已核对内容”保存。历史总结可以打开修改，旧版本不被覆盖。

点击“复制供 ChatGPT 分析”仅复制文本到剪贴板，需要本人到 ChatGPT 对话粘贴并请求润色、提取成就或分析，不表示网页在后台自动运行 ChatGPT。如果使用 Google Drive 连接器读取相关资料，仍应遵守文档权限及项目数据校验规则。

## 五、集中验收流程

仅在 2.4.0 组合候选全部测试通过后，使用 GitHub Actions 的独立 Windows 体验附件，不需要更改正式工作台。建议在临时测试目录中：
1. 创建一个虚构项目和任务，并给任务添加一步。
2. 暂存一条前几天的工作原文，整理为工作记录，关联虚构任务/步骤及虚构证据链接。
3. 补记另一条已完成工作，确认短编号、发生日期、录入日期和成果标识。
4. 编辑工作记录并刷新，确认内容仍在、日期修订不改变编号。
5. 从任务详情点“关联工作记录”查看历史。
6. 生成本周周报，人工补充、保存、再次修订，查看成果库。
7. 测试未保存修改时切页是否提醒，不使用真实工作资料。

体验附件使用独立临时服务和随机端口，不读取现有 Google Drive 工作台目录。启动脚本为 start_ui_v2_preview.bat；关闭启动窗口后临时测试数据清理。真正的两台公司电脑数据同步、断网与重连尚未实测，需要独立授权后再做增量验收。

## 六、功能边界

本机程序没有内嵌 AI、不使用模型 API，不会自动将会议识别为任务或将事实写成已完成。AI 分析由 ChatGPT 对话按用户要求进行；工作台的来源底稿不等于 AI 总结。任何真实数据、文件链接、人员和公司材料不得提交公开 GitHub。
