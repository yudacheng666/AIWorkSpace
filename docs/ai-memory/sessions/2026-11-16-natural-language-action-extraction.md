# 2026-11-16｜自然语言工作输入遗漏后续行动的规则修复

## 用户反馈
用户发现：在处理备件沟通和采购进展时，AI 有时只把自然语言写成工作记录（RECORD），没有分析同一段输入中产生的未来待办（TASK／STEP）。

## 案例归纳（已匿名化）
- 备件已转采购、等待报价／货源／交期：除了记录“已转采购”，还应建立或保留跟进反馈的待办。
- 已收到采购报价后，计划次日商定销售报价并在确认后通知销售：应分别建立两个有先后关系的步骤。
- 采购回复无货、已通知销售且用户明确结束事项：记录事实即可，不再创建无意义的后续待办。
- 早期询价流程还包含回收报价、整理销售报价、审批和回复客户等后续动作；只保存“已发询价”记录不足以管理完整工作链。

## 规则结论
- 用户要求记录、补记、同步或更新工作台时，必须执行“事实记录 + 行动提取”两轮分析；单纯咨询、头脑风暴和只读核查不自动写入。
- 不能只因用户说“记录”就只写 RECORD；但用户明确要求只记录时，尊重不创建待办的范围。
- 行动属于现有任务时优先写 STEP；独立行动才建 TASK。
- 等待外部反馈且仍需跟进时，必须有跟进待办；日期不明确不得猜测。
- 多步依赖拆成步骤，并在标题说明前置条件；不发明新字段。
- 纯信息、已完成动作、终局事项和未触发条件分支不强行变成待办。
- RECORD 与衍生行动通过当前 validator 支持的 `action_links` / `derived_action` 关联。
- 写入后分别回读记录和行动对象；汇报必须明确说明新增／更新待办，或说明为何无需新增。
