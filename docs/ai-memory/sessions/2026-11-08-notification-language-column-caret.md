# 2026-11-08：2.8.4 通知信箱可读性与任务列标题箭头修正

## 用户目标

根据用户在 AIWorkSpace 实际页面上的四处截图批注，修复：
1. 任务列表列标题的下拉箭头应紧跟标题，而不是在列右侧。
2. 通知信箱不能使用「这条记录」等不明确指代，必须显示具体关联任务和收到的操作内容。
3. 建议要告诉用户具体打开哪个任务、核对哪一步，以及如何通过正常业务入口处理。
4. 解释「原始文件／原始记录」究竟是什么、有什么用；更重要的是，界面不应要求普通用户理解或管理内部文件。

## 设计决策

- 将内部的事件文件/审计记录概念转换为业务语言：显示「收到的操作：新增/修改/删除步骤『名称』」，同时显示关联任务。
- 无效步骤操作的摘要说明系统未能确认目标，所以没有执行；影响说明现有任务和步骤没有因此改变。
- 新增、修改、删除分别给出对应的处理办法；目标不明确时先不要操作，可以复制消息给 ChatGPT 核查。
- 「暂不修复，保留原始记录」改为「暂不处理这项操作」。只保存用户的处理决定和备注，不应用这项操作，现有任务/步骤不变；这不代表异常已解决。
- 保留原有审计和业务安全边界，不改 API、事件 schema 或数据写入流程。
- 列标题下拉箭头独立于排序/筛选状态标记，始终紧邻字段名称。
