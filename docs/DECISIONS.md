# AIWorkSpace｜重要决策

日期：2026-10-27 起持续维护。只记录已确认的选择，以及首版正在验证的技术方向。

| 编号 | 决定 | 原因 / 状态 |
|---|---|---|
| D001 | AIWorkSpace 是全新独立项目，不继承旧项目代码或测试结论 | 简单从零开始 |
| D002 | 第一版只验证 ChatGPT 与网页的双向任务闭环 | 避免一次性开发过多功能 |
| D003 | 先个人使用，设计上保留未来团队扩展可能 | 先解决实际个人工作 |
| D004 | 优先 Google Drive 与现有 Windows 电脑，不默认增加付费云服务或 AI API | 跨设备、控制费用 |
| D005 | 用户已确认的需求统一维护于 `REQUIREMENTS.md` | 防止对话切换丢需求 |
| D006 | GitHub Markdown 文件作为跨对话/跨 AI 开发记忆；新 AI 必须主动读取和核实 | 项目可持续交接 |
| D007 | 本仓库 Public，绝不上传实际业务数据、个人隐私、密钥、授权凭证及敏感链接 | 防止公开泄露 |
| D008 | ChatGPT 负责开发、自测和维护；Codex 默认仅做独立验收；任务完成由用户手动确认 | 职责与权限清晰 |
| D009（核心链路已实测） | 首版采用 Python 标准库的 Windows 本机网页服务、Drive 桌面同步及每次追加独立 JSON 事件文件；事件发布必须原子且禁止覆盖，HTTP 必须校验本机 Host | 原两项 P2 已由 Codex Linux 独立复验通过；Linux/Windows CI 各 23/23 PASS；公司 Windows 电脑实测硬链接、Host 防护、双向同步、断网恢复、刷新持久性及旧版本写入保护。长时间稳定性尚未专项验证 |
| D010 | 当前阶段只部署和验收一台公司 Windows 电脑；不把第二台电脑并发测试列为交付门槛 | 用户明确当前只在公司电脑运行。重点验证单机服务与 Drive 桌面同步目录、ChatGPT 通过 Drive 连接器的读写闭环 |
| D011 | 验收用事件文件移入 `events/_archive_test_events_20261029` 子文件夹归档，不删除、不改写原始 JSON | 应用只读取 `events` 根目录的 JSON 文件；归档子目录保留证据但不进入日常任务列表。桌面同步后须刷新网页确认 |
| D012 | 暂缓远程访问；先完成 AIWorkSpace 产品功能，之后再基于届时的最新稳定版本补充远程访问 | 当前阶段不修改 M2/M3.1 的 Host/Origin 安全限制，不部署 Tailscale 远程入口；避免产品功能开发期间增加额外架构与验收范围 |

当前为低复杂度个人原型。事件 JSON 中的 actor 是声明字段，不是身份认证；任何 AI 写入都不得冒充用户已确认完成。若未来要求强身份保证，需另行设计可信写入路径，不在首版临时引入复杂认证。
