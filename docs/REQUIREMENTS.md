# AIWorkSpace｜产品需求 V1

状态：**用户已确认**（2026-10-27）。本文件记录产品需求，不代表全部功能已开发。

## 1. 定位和目标

以 ChatGPT 为主要自然语言/语音入口的个人 AI 工作台：AI 理解、记录、拆解、分析和跟进工作；网页集中查看、修改和人工确认。**先个人使用，未来扩展团队。**

## 2. 总体功能（分期实现）

| 功能 | 目标 |
|---|---|
| 工作输入 | 文字、语音；可将一段输入拆为多个事项 |
| 项目结构 | 项目、任务、明确编号的执行步骤；主要所属项目及相关项目 |
| 任务字段 | 负责人、状态、优先级、截止日期、计划执行日期、下次跟进日期（分开） |
| 工作台首页 | 今日需要亲自做、审核/决策、跟进他人、临近到期和风险事项 |
| 任务查询 | 按稳定编号、关键词/自然语言、项目、状态、时间等查找 |
| AI 助手 | 识别、归类、拆解、提出方案与优先级建议；能做的工作按授权执行 |
| 进度管理 | ChatGPT 文字/语音、网页操作、AI 执行结果均可更新进度 |
| 他人跟进 | 负责人、期限、最新进展、待反馈、下次跟进 |
| 想法与成果 | 将想法尽量转成行动；成果由用户审核后归档 |
| 历史与记忆 | 保存重要状态/计划/责任/决策变更及原因；支持跨对话读现有台账 |
| 主动提醒 | 截止/逾期、长期无进展、风险、冲突及汇总；网页、AI、手机渠道分期验证 |
| 数据安全 | 持久保存、备份恢复、避免离线/并发变更静默覆盖，引用有出处 |

## 3. 已确认的业务规则

1. 一次输入多个事项时，AI 自动拆分；需要确认的整理结果先展示再入账。
2. 缺乏必要信息先询问；例行新增、分类、进度更新及设置跟进日期可按已授权规则执行。
3. 重大优先级冲突，由 AI 给建议，用户确认后改变。
4. **所有任务完成状态只能由用户手动确认**；重大成果归档及冲突裁决也需要用户确认。
5. 他人负责的事项记录负责人、进度、期限、等待/阻碍原因及下一步，由用户与他人沟通。
6. 每个事项及明确步骤有稳定编号；支持按编号精确引用。
7. 一个事项以一个项目为主要归属，可关联其他项目；允许跨项目分析。
8. 只长期保留必要的结构化结果和重要历史，原始口述一般不长期保存全文。
9. 大项目先读覆盖历史的结构化总账，必要时深入明细；新对话主动读取既有历史。
10. 可检索用户已授权资料；发现资料新信息先提出建议，确认后更新台账，尽量提供编号及来源。
11. 新指令与现有状态相冲突时，明确指出并询问，不擅自改写。

## 4. 第一版：最小双向任务闭环

**仅需实现：**

1. ChatGPT 接收一项工作并整理为结构化任务。
2. 安全保存该任务，关闭对话后仍能读取。
3. 网页从同一份数据展示任务列表。
4. 用户在网页修改任务内容或进度，保存后 ChatGPT 能读取正确的新状态。
5. 明确“未保存 / 保存成功 / 读取失败”等基本反馈，避免静默丢失。

**验收标准：** AI 创建 → 网页可见 → 网页修改 → AI 读到更新后的值；重复操作和重新打开页面后仍正确。使用虚构测试数据。

项目/步骤完整功能、想法库、复杂筛选、人员跟进、自动提醒、手机推送及团队权限属于后续阶段，不在第一版一次完成。

## 5. 技术与费用约束

- 优先使用现有 Google Drive 与 Windows 电脑；可接受 ChatGPT 对话与网页分离。
- 优先云端维护开发内容与数据交互，不默认新增付费 Google Cloud 或 AI API。
- 存储结构、同步及备份方案需要先以最小实测确认；不能将技术探针当作正式产品验收。
- ERP 等敏感系统接口及外部平台对接不作为第一版范围。
- Public GitHub 只保存产品代码、非敏感设计和虚构测试数据；真实台账及凭证不进入仓库。

## 8. V2.0.1 小版本任务操作优化（用户 2026-11-02 决定优先推进）

1. **编号分离**：保留现有 `TASK-...` 内部 UUID 与 API、事件流、外键，不改写旧 JSON；在工作区读取结果增加可读短编号 `display_id`，由创建事件的 UTC 日期和内部 TASK ID 确定性派生。真实 UUID 的格式为 `T-YYMMDD-<12位大写十六进制前缀>`。非标准历史任务 ID 使用其 SHA-256 摘要前 12 位。无法确定日期时用 `000000`；同一工作区短编号发生碰撞时显示完整内部 ID 并明确提示，不静默错误引用。
2. **编号显示和复制**：任务列表、看板、日历、日期甘特、任务抽屉和项目任务列表优先显示 `display_id`；原内部 ID 仍用于真实保存、步骤/项目关联和 API。详情抽屉编号本身和旁边复制按钮都可点击复制，反馈真实复制结果。筛选支持显示编号与原 ID。
3. **抽屉交互**：仅点击任务详情抽屉之外的遮罩本体才关闭；点击抽屉内部不关闭；关闭必须复用既有未保存修改确认机制，取消时不能丢草稿。
4. **统一版本**：小更新以 `2.0.1` 为候选发布目标，但代码开发过程中不提前修改正式 `VERSION=2.0.0`；版本升级仅在通过验收并获用户发布批准后进行。build SHA 单独跟踪。
5. **工作记录/事件类型**：已经发生的事实不应被要求填写待处理/进行中等任务状态。该需求继续保留，但其数据结构与工作档案有关，2026-11-02 用户要求工作档案暂缓；2.0.1 不新增第二套工作记录数据层，不冒险将事实事件改写为“已完成任务”。工作档案恢复时统一实现记录类型及已有误分类事项的经确认转换。
6. **安全边界**：只在独立开发分支测试，不改 main、现有正式数据和云端事件，不触发收费 Actions，不自动合并或部署。


## 9. V2.0.2 三项任务管理功能（用户 2026-11-02 提出，独立开发中）

**版本定位**：属于 AIWorkSpace 统一版本，暂定 2.0.2 候选；在完整回归、风险验收和用户批准前，不修改 main 或正式 VERSION，不触及公司真实数据。个人工作档案继续暂停。

1. **回收站**：任务详情能将任务移到回收站；普通列表、项目统计、ChatGPT 默认任务查询不再出现已删除项；回收站显示删除时间、任务编号，提供恢复、勾选多条手动彻底删除。自动清空支持关闭／7／30／90 天，默认 30 天；仅在程序下一次被访问且数据无冲突、已到期时执行，不在程序停止时后台运行。永久删除写入不可复活墓碑事件，并尽量清除本机历史任务、步骤事件文件；墓碑必须先持久保存，才允许清理原文件。同步回来旧事件不能复活已彻底删除任务。Google Drive 跨电脑副本、云端历史和备份可能仍包含旧内容，不能承诺跨所有设备物理抹除。
2. **步骤状态联动任务**：不另写任务状态事件；按当前同步且无冲突的步骤求有效状态：任一步受阻→任务受阻；否则任一步进行中或已完成→任务进行中；全部待处理→任务待处理。全部步骤已完成→任务仍进行中，明确提示用户亲自确认任务完成，**绝不自动设置 done**；已经由用户确认完成的任务不因步骤编辑而悄悄取消完成。步骤未同步完整或存在冲突时，保留原任务状态并提示检查。任务事件中原 status / revision 不更改，API 返回额外的 manual_status、status_source、step_completion_pending。
3. **关联 Google Drive 文档**：每任务最多 20 个关联引用，按文档名称＋官方 HTTPS Google Drive / Docs / Sheets / Slides URL 保存，可添加、展示、打开和取消关联；不复制或删除云端原文件、不改变文档权限。URL 必须白名单校验，不接受 javascript、非 HTTPS、伪域名；写入现有任务追加式事件模型，revision/409 冲突保护延续。人工在各设备打开链接；ChatGPT 通过已授权 Google Drive 连接器，凭任务中的 URL/标识查找读取时依赖连接器本身的访问权限，**只保存链接不等于已自动接入文件或能保证 AI 读取**。公开 GitHub 仅放虚构链接作为测试。
4. **回收站入口与页面**：在左侧“系统导航”中设置与其他栏目同级的“回收站”导航项，打开主工作区独立回收站页面并显示当前导航高亮；“全部任务”页不再保留回收站按钮或浮层入口。回收站原有任务恢复、多选彻底删除、自动清空周期及安全确认行为均不改变，页面切换继续遵守未保存草稿保护。

## 14. 执行步骤删除与步骤级 Google Drive 文档关联（2026-11-03）
- 执行步骤在其行内增加“删除”，必须有明确二次确认；拒绝未保存草稿丢弃、任务/步骤冲突、步骤排序存在冲突或缺失、步骤版本过期时的删除。删除只写**步骤事件追加式墓碑**，不直接物理擦除步骤历史事件；删除步骤从列表、排序和任务状态联动汇总中排除，删除不会自动将任务置为完成。Google Drive 链接及原始文件不会被删除。允许清空全部执行步骤；延迟到达的旧事件不得让墓碑删除的步骤复活。
- **新文档仅关联步骤**：每步骤最多 20 个 Google Drive / Docs / Sheets / Slides 官方 HTTPS 文档链接，沿用链接白名单/去重/标题校验，按步骤独立 revision 与 409 冲突保护，支持新增、展示、打开和取消关联；不提供新任务级关联入口。一个链接可以分别关联不同步骤，但同一步骤中不可重复。
- **历史兼容**：升级前已存在的任务级 `document_links` 继续保留在原任务事件内、读取并显示为任务下的“历史任务级文档（只读）”。不根据内容猜测所属步骤、不自动移动或删除；旧任务级 POST 接口停止新增关联并返回 410。用户可按实际需要在相关步骤手工重新关联。步骤删除只隐藏当前步骤链接，保留原步骤事件证明，不更改 Google Drive 文件权限。
- 既有任务/项目字段、回收站任务删除与恢复、更新回滚、状态联动和草稿保护保持不变；不在获得明确批准前将此高风险事件模型变更合并 main 或部署真实双设备 Google Drive 数据。

## 15. 数据治理闭环：异常发现、人工核查、明确授权、合法写入、结果追踪（2026-11-03）

1. **异常发现**：工作台扫描 events/、project_events/、step_events/、settings_events/ 中的 JSON 事件，识别 JSON/编码错误、结构/业务规则校验失败；同时汇总任务、项目、步骤读取器已发现的版本冲突、引用缺失及同步等待。异常编号由来源目录、文件名和原始文件 SHA-256 确定，文件内容变化会形成新异常，不把不同版本混为一条。
2. **核查入口与原始证据**：侧栏有独立“数据核查”页面，完整显示待核查项、来源文件、原始事件/错误片段、事件 ID、任务/步骤引用、SHA-256、系统解释、建议修复预览及历史处理轨迹。所有扫描只读；不得自动改写、移动、删除或覆盖原始异常文件。异常不再只截取首页前三项。
3. **人工核查**：用户可以检查原始事件和建议，填写核查说明；不支持安全自动修复的异常，只能记录“已核查·不写入”及理由，不得用通用覆盖或猜测字段绕过校验。临时同步等待、跨版本引用和冲突继续显示，需待同步/冲突解决后重新扫描。
4. **明确授权（独立阶段）**：支持修复必须先展示确定的目标、当前 revision、合法字段变化及其 SHA-256 预览；用户点击确认后，将 authorize 决策作为追加式记录写入 review_events/。授权本身**不修改业务事件**。任务/步骤完成状态必须另行再次明确确认。授权后目标 revision、原始文件 hash 或提案发生变化，授权即失效，必须重新核查与授权。
5. **合法写入（独立阶段）**：用户再次点击“执行已授权修复”并确认后，后端重新校验原始文件 hash、目标存在性/冲突、当前 revision、提案 hash 和现有事件 schema validator，然后使用新 event_id、actor=user、当前 revision 追加一条合法事件。只支持可无歧义修复的已知类型：任务移入回收站/恢复的非法 lifecycle actor/revision；步骤 update 中可安全剔除的非法 position；缺少完成确认的任务/步骤完成事件（需再次确认）。purge、无目标/多义引用、无法解析 JSON、任意项目/设置异常等不自动猜测或写入，只能人工核查记录或由用户在专门业务界面处理。不得复用、篡改或删除原异常 event_id。
6. **结果追踪**：每次授权、拒绝写入、失效、失败和成功均在 review_events/ 追加独立审计事件；成功回执记录目标 event_id、文件名、SHA-256 和验证后的 revision。页面区分待核查、已授权待执行、已写入并验证、已核查不写入、过期、失败、冲突。每次展示已处理状态时复核结果文件是否存在、hash/内容是否仍与批准事件一致；结果文件缺失可重新核查授权，内容变化进入冲突、绝不覆盖。
7. **并发与同步**：核查记录自身使用 revision 事件流；同一 anomaly 的同 revision 并发授权/决定会冻结为冲突，不允许写入。Google Drive 同步到另一设备的“已授权”记录不会自动执行；本机必须重新展示提案并由用户明确点击执行。已应用结果和回执同步后可追踪。所有原始事件和核查审计均追加式保存。
8. **权限边界**：API 仍仅接受本机 Host/Origin。JSON 中 actor=user 只是审计声明，不等于强身份认证；本闭环依赖本机网页中的明确人工确认，不宣称具有企业级用户身份/角色认证。不得因同步文件内容而自动授权或执行。
9. **兼容与范围**：不迁移、不删除旧事件；新增 review_events/ 作为独立审计流。只使用虚构测试数据；不自动扫描或修改公司真实目录，不自动修复用户当前六条异常。正式发布和真实多设备 Drive 同步验收需另行批准。
