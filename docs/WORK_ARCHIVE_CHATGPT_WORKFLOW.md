# AIWorkSpace｜ChatGPT 与工作档案协同约定

状态：2.4.0 组合候选的工作流设计与边界说明。不是云端自动运行证明，也不是授权访问真实数据的令牌。

## 1. 有限自动化的实际能力

工作台本地 Python 服务不包含模型，网页只能收集原文、按规则校验并形成来源底稿。ChatGPT 在用户明确提出“记录今天的工作”“整理本周工作”“从工作档案撰写项目总结”等请求时，可以按可用的连接器权限读取 Google Drive 中的档案和任务资料并进行语义分析；有权限写入时也必须遵守当前仓库的事件规范与 revision/冲突检查，不能自行生成虚假完成确认。

未经验证，不承诺 ChatGPT 可在无人值守的定时任务里访问连接器并写回真实资料。工作台的“复制供 ChatGPT 分析”只是明确、可控的手动入口，不假装网页内有模型。

## 2. 将自由输入变为可追溯事实

例如用户说：“今天上午临时与两家供应商沟通交期，确认一家可按期供货；另有一家下周三需再核实。”

AI 应先核对现有项目、任务、工作记录和原文来源，区分：
- 已发生的沟通事实：创建或更新工作记录，发生日按用户时区；只记录明确事实和确认的成果，附件可关联 Google Drive 来源。
- 未来待确认的交期：检查已有采购任务/步骤，避免重复创建；如确需任务，给出清晰建议并遵守实际用户授权，不擅自将任何任务标记为完成。
- 日期和人员不明确时留空或请用户补充，不捏造责任或承诺。
- 同一句输入不能重复形成多条相同工作记录；如果来源来自 INBOX，必须保留 source_inbox_id 并核对是否已处理。

## 3. Drive 直写安全要求

真实写入前读取仓库 AGENTS.md、REQUIREMENTS.md、PROJECT_STATE.md、DECISIONS.md 和当前 app.py；确认当前数据目录的已有完整事件流、对象 ID、base_revision、重复 event_id、关联项目/任务/步骤是否存在、最新冲突状态，并对拟写事件执行与 app.py 同等的 schema 验证。不能把 Google Drive 上传成功当成工作台校验成功。

每次事件独立文件，禁止覆盖已存在的 events、step_events、record_events、inbox_events 或 summary_events。工作记录的发生日期与录入时间不可混为一谈；引用同一原文时不可重复整理。无法核实 revision、双机延迟同步或来源冲突时停止写入，保留来源并报告用户，不猜测重放。

用户在对话中叙述已做工作可以形成事实记录，但不等于授权直接修改原任务 status=done。实际任务或步骤完成仍需要明确人工确认并满足系统事件规则。

## 4. 日/周/月分析及归档

用户从网页生成的来源底稿包含工作记录、手动填写耗时、成果及明确确认的任务完成事件；AI 可以按项目归纳沟通、决策、问题、措施、结果、后续行动，同时保留引文来源 ID。不能把记录条数当成业绩，也不能把不确定讨论写成既定成果。输出建议包含：主要工作、已验证成果、问题与应对、后续行动、需用户核实的信息。

分析完成可由用户手动粘贴到工作台总结正文，再确认保存为 SUMMARY 事件。若通过连接器自动写回，也必须重新计算来源 ID 集合与当前状态，一旦不一致拒绝保存。外部报告、简历和职业成果文字均须人工审查后使用。

## 5. 隐私、版本与操作边界

所有业务事件只存个人指定的 data-dir / 私有 Google Drive，公开 GitHub 仅含代码、规则和虚构测试数据。不同电脑共享目录时先统一升级再启用新事件格式；真实双机离线重连与公司环境部署仍未验收。此工作流不增加付费 AI API 或自动访问公司内网。


## 6. 2.5.0 结构化行动建议协同

为避免 ChatGPT 和本地程序未经同意自动创建任务，采用人工审核中转流程：

1. 用户从工作记录页选择记录，点击“复制 ChatGPT 分析说明”，确认内容可用于当前聊天。复制不等于发送，也不意味着允许自动写入 Google Drive。
2. 在 ChatGPT 中粘贴，要求区分已发生事实与未来待办；最多五条明确待办，只返回严格 JSON（禁止 Markdown 代码围栏）：
   {"version":1,"record_id":"RECORD-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA","record_revision":1,"proposals":[{"title":"下周核对虚构供应商的交期","due_date":null}]}
   如果没有可信后续行动，应说明无新增任务，不应强行编造日期或任务。
3. 将 JSON 粘贴回工作台，服务端执行 schema、来源 revision 和当前同项目任务查重。标题相似度只是确定性辅助，不是 ChatGPT 的语义去重或在线全库查询。
4. 用户逐条确认关联已有任务或新建待办；任何取消、409、错误 JSON、未同步来源均不写任务。正式任务默认 todo，创建事件不可包含 done；source_work_record 只读保存来源。
5. 真实云端 Drive 直写及主动复盘仍必须先审计仓库规则、业务 event schema、数据目录全量 revision 与同步状态，不能使用未经确认的猜测。这个阶段不实现无人值守聊天自动任务生成，仍需用户亲自点击。

重要边界：工作记录内容与任务名称是私有业务信息；复制到剪贴板需要用户明确操作。任何敏感内容都不写入公开 GitHub 测试、示例或日志。
