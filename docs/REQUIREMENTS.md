# AIWorkSpace｜产品需求 V1

状态：**用户已确认**（2026-10-27）。本文件记录产品需求，不代表全部功能已开发。

## 1. 定位和目标

以 ChatGPT 为主要自然语言/语音入口的个人 AI 工作台：AI 理解、记录、拆解、分析和跟进工作；网页集中查看、修改和人工确认。**先个人使用，未来扩展团队。**

## 2. 总体功能（分期实现）

| 功能 | 目标 |
|---|---|
| 工作输入 | 文字、语音；可将一段输入拆为多个事项 |
| 项目结构 | 项目、任务、明确编号的执行步骤；主要所属项目及相关项目 |
| 任务字段 | 负责人、状态、优先级、截止日期、计划执行日期、下次跟进日期（分开） |
| 工作台首页 | 今日需要亲自做、审核/决策、跟进他人、临近到期和风险事项 |
| 任务查询 | 按稳定编号、关键词/自然语言、项目、状态、时间等查找 |
| AI 助手 | 识别、归类、拆解、提出方案与优先级建议；能做的工作按授权执行 |
| 进度管理 | ChatGPT 文字/语音、网页操作、AI 执行结果均可更新进度 |
| 他人跟进 | 负责人、期限、最新进展、待反馈、下次跟进 |
| 想法与成果 | 将想法尽量转成行动；成果由用户审核后归档 |
| 历史与记忆 | 保存重要状态/计划/责任/决策变更及原因；支持跨对话读现有台账 |
| 主动提醒 | 截止/逾期、长期无进展、风险、冲突及汇总；网页、AI、手机渠道分期验证 |
| 数据安全 | 持久保存、备份恢复、避免离线/并发变更静默覆盖，引用有出处 |

## 3. 已确认的业务规则

1. 一次输入多个事项时，AI 自动拆分；需要确认的整理结果先展示再入账。
2. 缺乏必要信息先询问；例行新增、分类、进度更新及设置跟进日期可按已授权规则执行。
3. 重大优先级冲突，由 AI 给建议，用户确认后改变。
4. **所有任务完成状态只能由用户手动确认**；重大成果归档及冲突裁决也需要用户确认。
5. 他人负责的事项记录负责人、进度、期限、等待/阻碍原因及下一步，由用户与他人沟通。
6. 每个事项及明确步骤有稳定编号；支持按编号精确引用。
7. 一个事项以一个项目为主要归属，可关联其他项目；允许跨项目分析。
8. 只长期保留必要的结构化结果和重要历史，原始口述一般不长期保存全文。
9. 大项目先读覆盖历史的结构化总账，必要时深入明细；新对话主动读取既有历史。
10. 可检索用户已授权资料；发现资料新信息先提出建议，确认后更新台账，尽量提供编号及来源。
11. 新指令与现有状态相冲突时，明确指出并询问，不擅自改写。

## 4. 第一版：最小双向任务闭环

**仅需实现：**

1. ChatGPT 接收一项工作并整理为结构化任务。
2. 安全保存该任务，关闭对话后仍能读取。
3. 网页从同一份数据展示任务列表。
4. 用户在网页修改任务内容或进度，保存后 ChatGPT 能读取正确的新状态。
5. 明确“未保存 / 保存成功 / 读取失败”等基本反馈，避免静默丢失。

**验收标准：** AI 创建 → 网页可见 → 网页修改 → AI 读到更新后的值；重复操作和重新打开页面后仍正确。使用虚构测试数据。

项目/步骤完整功能、想法库、复杂筛选、人员跟进、自动提醒、手机推送及团队权限属于后续阶段，不在第一版一次完成。

## 15. 数据治理闭环：异常发现、人工核查、明确授权、合法写入、结果追踪（2026-11-03）

1. **异常发现**：工作台扫描 events/、project_events/、step_events/、settings_events/ 中的 JSON 事件，识别 JSON/编码错误、结构/业务规则校验失败；同时汇总任务、项目、步骤读取器已发现的版本冲突、引用缺失及同步等待。异常编号由来源目录、文件名和原始文件 SHA-256 确定，文件内容变化会形成新异常，不把不同版本混为一条。
2. **核查入口与原始证据**：侧栏有独立“数据核查”页面，完整显示待核查项、来源文件、原始事件/错误片段、事件 ID、任务/步骤引用、SHA-256、系统解释、建议修复预览及历史处理轨迹。所有扫描只读；不得自动改写、移动、删除或覆盖原始异常文件。异常不再只截取首页前三项。
3. **人工核查**：用户可以检查原始事件和建议，填写核查说明；不支持安全自动修复的异常，只能记录“已核查·不写入”及理由，不得用通用覆盖或猜测字段绕过校验。临时同步等待、跨版本引用和冲突继续显示，需待同步/冲突解决后重新扫描。
4. **明确授权（独立阶段）**：支持修复必须先展示确定的目标、当前 revision、合法字段变化及其 SHA-256 预览；用户点击确认后，将 authorize 决策作为追加式记录写入 review_events/。授权本身**不修改业务事件**。任务/步骤完成状态必须另行再次明确确认。授权后目标 revision、原始文件 hash 或提案发生变化，授权即失效，必须重新核查与授权。
5. **合法写入（独立阶段）**：用户再次点击“执行已授权修复”并确认后，后端重新校验原始文件 hash、目标存在性/冲突、当前 revision、提案 hash 和现有事件 schema validator，然后使用新 event_id、actor=user、当前 revision 追加一条合法事件。只支持可无歧义修复的已知类型：任务移入回收站/恢复的非法 lifecycle actor/revision；步骤 update 中可安全剔除的非法 position；缺少完成确认的任务/步骤完成事件（需再次确认）。purge、无目标/多义引用、无法解析 JSON、任意项目/设置异常等不自动猜测或写入，只能人工核查记录或由用户在专门业务界面处理。不得复用、篡改或删除原异常 event_id。
6. **结果追踪**：每次授权、拒绝写入、失效、失败和成功均在 review_events/ 追加独立审计事件；成功回执记录目标 event_id、文件名、SHA-256 和验证后的 revision。页面区分待核查、已授权待执行、已写入并验证、已核查不写入、过期、失败、冲突。每次展示已处理状态时复核结果文件是否存在、hash/内容是否仍与批准事件一致；结果文件缺失可重新核查授权，内容变化进入冲突、绝不覆盖。
7. **并发与同步**：核查记录自身使用 revision 事件流；同一 anomaly 的同 revision 并发授权/决定会冻结为冲突，不允许写入。Google Drive 同步到另一设备的“已授权”记录不会自动执行；本机必须重新展示提案并由用户明确点击执行。已应用结果和回执同步后可追踪。所有原始事件和核查审计均追加式保存。
8. **权限边界**：API 仍仅接受本机 Host/Origin。JSON 中 actor=user 只是审计声明，不等于强身份认证；本闭环依赖本机网页中的明确人工确认，不宣称具有企业级用户身份/角色认证。不得因同步文件内容而自动授权或执行。
9. **兼容与范围**：不迁移、不删除旧事件；新增 review_events/ 作为独立审计流。只使用虚构测试数据；不自动扫描或修改公司真实目录，不自动修复用户当前六条异常。正式发布和真实多设备 Drive 同步验收需另行批准。

## 23. 步骤日期、日历/甘特展示与任务/步骤互转（2026-11-05，2.1.0）

### 步骤日期
- 执行步骤沿用任务现有的三种日期字段：计划执行日期 \`planned_date\`、截止日期 \`due_date\`、下次跟进日期 \`follow_up_date\`。当前任务数据模型是**日期（YYYY-MM-DD）**，本需求不另造时分秒字段。
- 步骤可在步骤编辑区独立设置、修改和清空三种日期；使用原 step revision、追加式 \`step_events\`，校验真实日历日期，禁止客户端设置步骤 position。
- 任务日历同时显示任务和步骤，按用户选定的三种日期字段筛选；无日期事项进入未设置日期列表。日历点击步骤打开所属任务详情并定位步骤。
- 甘特图同时显示任务和步骤；与任务一致，计划日期和截止日期形成展示窗口，下次跟进日期不绘制甘特条；没有计划/截止日期、日期冲突或数据冲突的事项不强行绘制。

### 双向转换
- **步骤→任务**：用户在步骤行明确确认后，将步骤移动为其当前所属任务的子任务。新任务保留标题、状态、三种日期、文档链接；新任务编号重新生成，原步骤编号及完整事件历史保留在转换事务/原事件流中。
- **任务→步骤**：用户明确选择目标父任务并确认后，将任务移动为目标任务的执行步骤。只允许末级任务（没有活动或回收站子任务、没有活动执行步骤、没有未解决父子/状态冲突）；复杂任务须先处理下级事项，不能静默扁平化或丢弃。
- 任务转步骤时保留标题、状态、日期、文档链接；负责人、优先级、项目归属及原父任务引用保存在步骤的受控转换元数据中，日后转回任务可恢复。步骤转任务时，普通步骤继承所属任务的项目关联；若步骤来自先前任务转换，则恢复其保留的负责人、优先级和项目关联。
- 转换是**移动而非复制**：原任务/步骤对象在有效转换后不再作为活动对象显示，转换后分配新的目标类型编号；原任务/步骤事件文件不覆盖、不删除。任务父子和步骤状态汇总在投影时重新计算。
- 每次转换写入一个独立 \`conversion_events\` 追加式事务文件，包含源 revision、源对象指纹、目标 ID/字段和用户确认；读取时仅当源指纹仍匹配且目标/父任务可验证才激活转换。同步不完整时暂不显示目标、保留源；源发生并发修改时冻结转换目标并保留源、发出核查警告；重复/冲突转换不会双重显示。转换链按依赖顺序解析。
- 转换目标后续被删除/永久清空时，源不自动复活；源在转换后被并发删除或修改时，不会自动覆盖目标，转换转入核查状态。
- 转换链有三次以上依赖时，解析顺序必须基于上游目标的依赖关系，而非云端文件名或同步到达顺序；无效循环及竞争转换不能激活目标。
- 从云端同步取得的 conversion_events 即使通过 JSON schema，也必须核对目标字段与源的真实内容一致（标题、原有效状态、日期、文档链接、受控的原任务负责人/优先级/项目元数据），不允许借“转换”伪造已完成或更改无关业务字段。
- 不允许将事项移入已人工确认完成、冲突、回收站、父子关系异常或步骤排序不完整的目标父任务。转换和日期编辑都必须使用当前 revision，过期返回 409。
- **多设备兼容**：新步骤日期事件与转换事务需要 2.1.0 客户端识别；用户在同一 Google Drive 数据目录的所有电脑更新到 2.1.0 之前，不应在不同版本客户端之间交替编辑或执行转换。旧版不会完整识别新日期/转换记录，可能产生旧视图或 revision 冲突。

## 自动处理可安全接续的修改（2026-11-06）

用户批准：同一任务或步骤的多个更新如果因 Google Drive 同步/并发产生相同 `base_revision`，程序应优先识别是否可以安全自动归并，避免要求用户逐条复制给 ChatGPT。

- **低风险自动归并**：只处理修改字段互不重叠、事件都经过原有格式校验且具备合法时区时间戳的并发 `update`；任务仅限名称、负责人、优先级、截止/计划/跟进日期；步骤仅限名称及日期。无论文件同步顺序如何，结果一致，时间戳只作提示，不能决定同字段胜负。
- **高风险保持人工核查**：同字段不同值或同字段重复修改、完成/状态、删除/回收站、排序、周期规则、所属项目、父子关联、文档链接、任务/步骤转换、重复事件 ID 等不自动处理；无法证明完整同步、出现非法文件或版本链不完整时同样冻结，保留原始证据。
- **不变式**：独立并发事件在只读投影中成为一个逻辑修订；全部事件字节保持原样，不能按时间覆盖、物理删除或偷偷重建。投影生成稳定的合并凭证（参与事件内容指纹）；随后本机合法写入必须带该凭证，旧客户端或云端无凭证的后续写入不能覆盖合并结果，必须停下核查。
- **通知简化**：自动归并只产生非待办的“已自动整合”消息，注明涉及的业务字段、原文保留、无需处理；不显示需要人工选择或 ChatGPT 的按钮。仅不确定/危险异常保留“复制给 ChatGPT 核查”。
- **验收**：需覆盖独立字段、同字段竞争、乱序/晚到同步、重复 ID、凭证失配、删除/完成竞争、步骤独立字段及 Windows 真正浏览器下一次写入。云端 CI 不等于真实双机 Drive 实机验收。未经明确授权不修复历史工作数据、不自动更新用户的 Windows 工作台。

## 2.8.2：通知信箱交互稳定性与视觉一致性（2026-11-06）

- 通知信箱的“查看详情”“暂不修复，保留原始记录”及修复预览在后台周期刷新、人工刷新后不得自动折叠；用户未提交的理由输入、勾选确认保持可见与可用，但**只有来源 SHA、proposal、消息状态与核查修订号未变**才恢复原先勾选，避免跨版本误授权。
- 用户离开页面或明确收起可关闭详情，不能以后台刷新来重置交互。打开多个消息应各自保存展开状态，不得错配到另一条消息。
- 所有核查确认勾选框、说明文字、文本输入在常见桌面和较窄窗口中正常对齐，不应被全局表单输入宽度挤压到一侧，也不应产生操作面板横向溢出。
- 左侧通知数量和标题同行；风险事项导航的行高、图标与上下间距和同组菜单统一；“刷新消息”与现有按钮视觉统一；顶栏刷新、补记工作、新建任务高度统一，文字按钮的字号和字重统一。
- 必须在原始事件保持不变的合成数据上测试，真实 Chromium E2E 要等待超过一个后台实际轮询周期，验证展开、理由输入、确认及最终单条审计操作；手动刷新也不得使草稿丢失。

## 30. 统一进展时间线与个人／汇报版总结（2026-11-09，设计批准并推进候选）

- 项目、任务和步骤详情中直接快速记录已发生进展和沟通。每条只有一个不可变 RECORD ID；存于已有 `work_archive/record_events` 追加式事件目录。同一个事实可以在步骤、任务、项目、个人工作轨迹中显示，按来源 ID 去重，不复制工作记录或改变原 task/step/project 事件。
- 快速记录默认内容＋实际发生日期；关联当前业务对象。状态保持不变，完成状态仍必须人工确认；冲突、目标缺失、草稿未保存时拒绝危险写入。
- 同一工作记录关联多个项目／任务／步骤时，时间线展示来源与关系；全局汇总不能因为多处显示而多次统计。步骤／任务的快速进展属于个人工作轨迹，可作为日周月项目报告候选来源。
- 工作总结新增**个人版**和**汇报版**：个人版默认包含全部符合时间与项目范围的事实；汇报版让用户逐条勾选或取消本次纳入的工作记录和人工确认任务完成事件。可以全选、全取消、按明确规则推荐重点；无论选择如何，所有历史记录仍完整保存并在个人轨迹可见。
- `SUMMARY` 保存本次 `audience`、完整候选来源 ID 集合和实际 included 来源 ID 子集及正文、revision；不在 RECORD 上写全局“不参与汇报”标记。已确认的旧 SUMMARY 若无新字段按个人版和全部来源解释，不覆盖旧事件。
- 只向 ChatGPT 复制本次**明确选中**的来源，不把未选记录混入 AI 语义分析；保存前重核候选来源全集，有新增／缺失或冲突时返回 409、提示重新选择。报告正文编辑和来源选择必须一致，不能在取消勾选后沿用包含已取消内容的旧底稿直接保存。
- 不使用付费模型 API；定时规则汇总与后台 AI 语义报告是不同能力，本期不承诺无人值守 AI 报告。具体数据架构、界面、风险和逐阶段验收见 `docs/UNIFIED_WORK_TIMELINE_V2.md`。

## 31. Windows 无控制台桌面启动与关闭（2.9.2）

1. **无需 EXE 或安装包**：提供标准 Windows Script Host（VBS）入口和 Python 标准库启动管理程序；不新增第三方依赖，不要求用户每次打开 PowerShell。
2. **每台电脑首次设置一次**：用户双击 `setup_desktop_shortcuts.vbs`，选择现有 AIWorkSpace 数据根目录；脚本在桌面创建「AI 工作台」和「关闭 AI 工作台」快捷方式。每台电脑的 `launcher.json` 单独保存在 `%LOCALAPPDATA%\AIWorkSpace\`，不进入 GitHub、Google Drive 或业务数据目录。
3. **数据路径保护**：必须选择已存在的数据根目录，不得选择 `events`、`project_events`、`step_events` 等子目录；程序目录和数据目录不得相互包含。不得把任何真实公司路径写入公开仓库。
4. **启动行为**：使用现有 Python 安装（优先 `pythonw.exe`，必要时隐藏启动 `python.exe`），后台运行现有 `app.py`，保留原 `--data-dir` 和 8770 端口。先检查本机服务：健康接口确认就绪后才打开浏览器；若已是 AIWorkSpace 旧版，则只打开现有实例；端口被其他程序占用时拒绝启动，不得重复启动或终止未知进程。
5. **安全关闭**：启动器为每次服务实例生成随机控制凭证，服务只在直接 loopback 请求、无代理转发头且凭证正确时接受关闭请求。关闭只针对本次由桌面启动器启动的服务，不使用 `taskkill`、不按端口杀进程、不影响其他 Python 程序。旧 PowerShell 手动启动的实例没有控制凭证，首次切换时需用户手动关闭一次。
6. **日志与清理**：错误日志放在本机 `%LOCALAPPDATA%\AIWorkSpace\logs\`，单文件上限 512 KB、最多保留一个轮换副本；运行状态与启动锁放在本机 `run\`。禁止把运行日志、PID、凭证写入 Google Drive 业务数据目录。
7. **软件更新兼容**：启动管理程序和三个 VBS 脚本纳入 updater 白名单、备份及回滚。升级失败时，旧版本原本不存在的新脚本必须在回滚时移除；数据目录字节保持不变。
8. **验收**：覆盖健康检查、旧版本识别、重复启动、非工作台端口占用、控制凭证缺失/错误/正确、代理转发关闭拒绝、旧 PowerShell 实例不被误停、更新备份与回滚；Windows CI 检查 VBS 入口与隐藏启动参数。真实公司电脑只需每台首次运行设置脚本，不在 CI 中访问真实数据。
